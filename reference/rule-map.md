# Rule map — FTC requirement → citation → tag → check

The FTC's compliance guide (`ftc-compliance-guide.md`) states 8 bolded requirement-headers. `can-spam-auditor` checks **7 operative rules** — header 6 ("Remember that subscribers and members can opt out of marketing emails, too") is the FTC's own clarifying note that Rule 5's opt-out duty still applies to subscribers/members unless the message is genuinely a "transactional or relationship" message (a primary-purpose judgment defined in `ftc-compliance-guide.md`'s Q&A section and 16 CFR §316.3) — it doesn't add a new mechanically-checkable structural rule of its own, so it's folded into Rule 5's scope note below rather than given a separate check. It is NOT dropped from `reference/` — the full guide text carries it verbatim.

| # | FTC requirement (guide header, verbatim) | Citation | Tag | Check function (`audit.py`) |
|---|---|---|---|---|
| 1 | "Don't use false or misleading header information." | 16 CFR §316.2(m) (sender definition); FTC guide | `AUTOMATED` | `check_header_accuracy()` — fails if `From` is missing/unparsable, or `Reply-To` (when present) resolves to a different domain than `From` |
| 2 | "Don't use deceptive subject lines." | 16 CFR §316.3(a)(2)(i)–(ii) (primary-purpose subject-line test) | `AUTOMATED` *(narrow slice only)* + `AI-ASSISTED` (everything else) | `check_subject_line()` — fires `AUTOMATED FAIL` only for the specific §316.3(a)(2) structural pattern (subject reads transactional, body opens with commercial content and no transactional content up front); any other subject-line judgment is emitted as `AI-ASSISTED — needs human/model review`, never silently passed |
| 3 | "Identify the message as an ad." | FTC guide (implements 15 U.S.C. 7704(a)(5)) | `AUTOMATED` | `check_ad_disclosure()` — fails if no explicit ad/advertisement/promotional-message disclosure phrase is present in the body |
| 4 | "Tell recipients where you're located." | 16 CFR §316.2(p) ("valid physical postal address") | `AUTOMATED` | `check_postal_address()` — fails if no street-address or PO-Box or ZIP-code-shaped pattern is present in the body |
| 5 | "Tell recipients how to opt out..." | 16 CFR §316.5 | `AUTOMATED` | `check_opt_out()` — **one gate, two boundaries in the same pass**, per §316.5's own text: fails if no opt-out mechanism is present at all; separately fails if the mechanism appears fee-gated (`$`/fee/charge language adjacent to opt-out instructions) OR multi-step (language implying more than "a reply email or visiting a single Internet Web page" — e.g. "call", "mail a letter", "log in and navigate to"). **Scope note (folds in FTC header 6):** this check applies regardless of subscriber/membership status — the guide is explicit that subscribers/members don't lose the opt-out right unless the message is genuinely transactional-or-relationship per §316.3(c); `audit.py` doesn't attempt that judgment call and says so in its output rather than assuming either way. |
| 6 | "Honor opt-out requests promptly" (within 10 business days) | 16 CFR §316.5(b); FTC guide | `OUT-OF-SCOPE` | none — named explicitly in README and CLI output. A static single-email auditor has no way to observe what happens after the email is sent. |
| 7 | "Monitor what others are doing on your behalf" (third-party sender accountability) | FTC guide (implements 15 U.S.C. 7704(a)) | `OUT-OF-SCOPE` | none — same treatment. Auditing a third party's ongoing conduct is not something a single static artifact can check. |

## Label integrity — provable, not narrated

`audit.py --selftest` includes a **label-integrity pass**: it inspects the source of every function tagged `AUTOMATED` above (via `inspect.getsource`) and fails the selftest if any of them references `urllib`, `requests`, `http`, `openai`, `anthropic`, or any other network/LLM call. An `AUTOMATED` finding that secretly asked a model would fail this check, not just look suspicious in a code read. `AI-ASSISTED`-tagged code paths are exempt from this check by design — they're allowed to say "ask a human or a model," they just have to say so.

## §316.4 (sexual-content warning labels) — not wired into the default rule set

`16-cfr-part-316.md` carries the full text of §316.4 (verbatim, part of the complete regulation), but `audit.py` does not check for it by default — it's a conditional requirement (only triggers when a message contains sexually oriented material, which this auditor has no way to detect in a general marketing-email context) rather than a universal one like Rules 1–5. Included in `reference/` for completeness and because a reader checking "does `reference/` contain the whole regulation, not a curated subset" should find the whole regulation.
